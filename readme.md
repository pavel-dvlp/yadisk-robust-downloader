# Скачиватель файлов из яндекса

Скрипт позволяет последовательно скачать все доступные файлы из яндекс облака, не прерываясь при недоступности файла.

Для работы нужно обязательно указать целевую папку, куда сохранять скаченные файлы (аргумент --base-dir)

Таймаут на скачивание по умолчанию -- 3 сек. Однако практика показала, что действительно иногда
сервера яндекса подтормаживают, и может иметь смысл ждать 10 или даже 15 секунд, но не больше. 
Оценивайте сколько у вас файлов. С таймаутом 10 сек 10000 при большом проценте неудач могут скачиваться больше суток.

В ту же папку скрипт сохранит список файлов *yadisk-robust-downloader-file-list.txt*, 
там пишется 3 колонки: путь, дата изменения, размер

При запуска скрипта с аргументом *--scan* скрипт только сопоставит содержимое целевой папки с 
списком файлов из *yadisk-robust-downloader-file-list.txt*, выведет короткий текстовый отчёт на терминал
и сформирует более подробный отчёт в файле *yadisk-robust-downloader-stat.txt*

Если файл *yadisk-robust-downloader-file-list.txt* существует, то скрипт не будет заново запрашивать 
список файлов из облака, предполгается, что файлы не редактируются и не добавляются между итерациями скачивания.

При очередной итерации скрипт будет пытаться качать только недостоющие файлы и файлы, которые скачились не полностью.

Флаг *--fix-size* позволяет попробовать перекачать только скаченные неполностью файлы, имеет смысл попробовать сделать 
это с повышенным таймаутом, если такие файлы есть.

### Безопасно ли авторизовывать приложение yadisk-robust-downloader в яндексе?
Скрипту нужен токен от яндекса, для этого нужно авторизоваться по ссылке
https://oauth.yandex.ru/authorize?response_type=code&force_confirm&client_id=0600fcb8a139447a9211b35d0bc630e6&redirect_uri=https://oauth.yandex.ru/verification_code&code_challenge=This_string_must_be_at_least_43_character_long&code_challenge_method=plain.
После этого вы получите код авторизации. Этот код нужно будет ввести по запросу скрипта.
Затем скрипт обменяет код на токен, которым будет авторизовавать дальнейшие запросы к Яндексу. 
Можете изучить исходные коды и убедится, что токен не отправляется ни на какие сторонние сервера. 
Аналогично с кодом авторизации, можете обратить внимание, что в ссылке авторизации в redirect_uri
стоит заглушка яндекса *https://oauth.yandex.ru/verification_code*, которая просто показывать код
юзеру на экране. То есть, нексмотря на то, что кажется, будто вы даёте права какому-то веб-приложению,
никакие коды или токены никогда не передаются за пределы яндекса и тем более ни на какие сервера,
связанные с разработчиком настоящего скрипта. Просто у яндекса нет отдельного протокола авторизации
для standalone приложений, поэтому приходится пользоваться инструментами от веба с костылями в виде
страниц-заглушек и ручного ввода кода авторизации в скрипт.

После успешной авторизации скрипт напечатает в терминале токен, если понадобится запускать скрипт 
несколько раз, можно прихранить токен где-нибудь и передавать в скрипт с аргументом **--token**, 
тогда код авторизации запрашиваться не будет.
